# Landing page design spec

Status: foundation spec for future frontend work. No frontend implementation is created by this document.

## Source basis

- Canonical product: `docs/V0/V0.md`.
- Claim language: `docs/Project/Design/PROJECT_CONTENT_AND_LANGUAGE_GUIDE.md`.
- Visual system: `docs/Project/DESIGN.md`.
- Visual-only references: local video generation references and landing references.

## First viewport

- Signal the product name, India-first real-estate use case and proof-first workflow immediately.
- Hero visual should show a product-shaped system: approved brand truth, candidate/source evidence, script selection, 9:16 video, cost state, review and verified publication.
- Do not use vague "AI magic", guaranteed virality, guaranteed performance, or unsupported neurology/scientific claims.

## Section architecture

1. Hero: brand truth to verified video, with a product composite instead of stock abstraction.
2. Brand truth: approved profile, evidence, locked rules and human approval.
3. Viral discovery: source identity, observed metrics, snapshot date, rights warning and candidate choice.
4. Blueprint to video: thumbnail, scene stages, formula, director prompt and script variants.
5. Human approval and cost: avatar eligibility, estimate, maximum authorisation, reserve/capture/release.
6. Publish with proof: scheduling, platform submission, audience verification and notification after verified state.
7. Lineage and performance evidence: immutable ancestry, ledger and observed metric snapshots.
8. CTA: request access or create first production only when the implemented product supports it.

## Visual direction

- Dark-mode-first premium SaaS with cinematic media objects.
- Swiss/Modernist grid and typography discipline.
- Luxury minimal surfaces with Art Deco-inspired linework used sparingly for premium trust.
- Tech-forward glass and gradient only around product composites and evidence layers.
- Motion is kinetic but controlled: stage progression, timeline movement and reveal of evidence.

## Conversion rules

- CTA labels must be concrete and backed by implemented capability.
- Public page copy must say "observed", "estimated", "approved", "verified" and "retained" only where the product contract supports it.
- Xpoz may appear only as source/provider identity inside evidence if canonical UI copy allows it; public value prop should say viral discovery adapter/source evidence.
