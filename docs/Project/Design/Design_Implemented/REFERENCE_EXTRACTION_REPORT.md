## Video_generating.html

Factual extraction:

- Dark, high-contrast app shell with a sticky left navigation rail, a top utility bar, a large dashboard hero, a three-column work area and lower queue/assets panels.
- Palette is near-black graphite with a loud yellow/amber creative accent, cream text, translucent panel borders, cyan/blue utility accents and red alert accents.
- Typography uses a geometric sans for interface copy and a mono family for labels, IDs, small metrics and technical metadata.
- Layout language is dense command-centre UI: sidebar, hero metrics, input panel, central 9:16 phone preview, right scoring panel, timeline and queue.
- Interaction language includes hover lift, active pill tabs, range sliders, modal progress, animated meters, live-dot status, moving grid/scanline texture and floating phone motion.
- Useful SaaS patterns: 9:16 preview as primary object, scene timeline, generation queue rows, asset cards, score grid, stage pipeline, input sliders and progress modal.
- Risks for Sakhaa Forge: yellow as dominant brand accent conflicts with `DESIGN.md` Iris/Ember; text contains V1/V2/scoring claims that V0 cannot expose as product promises; generated percentages are decorative unless backed by retained evidence.

## Video_generating_light.html

Factual extraction:

- Light command-centre variation using white, cream, ink, yellow and amber with soft shadows and stronger black borders.
- Same major objects as dark version: sidebar, topbar, hero, brief form, phone preview, timeline blocks, score panel, asset cards and render queue.
- Better readability than the dark reference for long forms, but stronger shadow/card treatment risks a generic SaaS template feel.
- Component behaviours: selectable chips, range controls, modal generation flow, keyboard shortcut, responsive collapse to one column, hover-raised cards and animated meters.
- Useful product patterns: top breadcrumb, compact input stack, preview plus progress stack, status tags, export settings panel.
- Risks for Sakhaa Forge: over-rounded cards, heavy drop shadows and repeated metric tiles should be reduced in authenticated V0 UI; copy contains unsupported prediction language and must not be reused.

## Cross-reference extraction

Reusable visual language:

- A "studio instrument" product UI should centre the video object and surround it with evidence, lineage, cost and status.
- The strongest pattern is not the metric hero. It is the vertical video preview connected to timeline, formula, script, status and retained artifact evidence.
- The app can use controlled creative energy through animated stage spines, timeline segments, media previews and progress states, while irreversible actions stay calm.
- Dark mode is best for media review and generation context; light mode is best for dense forms, approvals, tables and administration.

Rejected or limited:

- Dominant neon yellow, fake live percentages, unsupported "brain score" or "performance tested" claims, decorative scanlines everywhere, high letter-spacing uppercase labels, excessive rounded cards and duplicated card grids.
- Internal names such as Xpoz remain adapter/source identity unless canonical UI documents require showing them as source evidence.
